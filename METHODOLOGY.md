# Methodology — what a Murmur run is, and what it is not

Read this before quoting a number from a Murmur report. It is short on purpose.

## The one-sentence version

Murmur asks a language model to invent a panel of critics, has each of them
write posts, scores that invented text with a lexicon, and runs a deterministic
social graph over the result. **The output is a structured set of arguments, not
a measurement of people.**

## What is real

- **The engine's arithmetic is deterministic and replayable.** Same seed, same
  inputs ⇒ byte-identical world, byte-identical report. This is enforced by a
  golden test, not merely documented.
- **The engine never calls a model and never touches the network.** A run is
  powered by the LLM you are already paying for, inside your coding session.
  The shipped bundle is scanned for network APIs, URLs, and key surfaces by a
  release gate.
- **Every figure in the report is verified against the run that produced it.**
  The engine extracts each number from the narrative and requires it to resolve
  to a value this run actually produced; a draft stating a number the run does
  not contain is rejected with the field and the value named.
- **Every claim traces to a post.** A cited post id must resolve in the
  database, and every quote is the literal text of that post.

## What is not real

- **The personas are invented.** They are archetypes generated by a model from
  your seed material. They are not your customers, and they are not a sample of
  anyone. No persona is ever derived from or attributed to a real individual.
- **The sentiment scores are lexical.** `sentiment.ts` is a curated ~200-term
  lexicon with negation and intensifier handling, bounded with `tanh`. It
  measures which words a model chose to write. It is not sentiment analysis of
  human beings, and it is not calibrated against any human dataset.
- **The P10–P50–P90 band is a sensitivity analysis, not an uncertainty
  interval.** `dynamics/ensemble.ts` fits a least-squares line to the observed
  sentiment curve and jitters the fitted slope by ±0.06 across refits. No part
  of the mechanism is re-simulated, and the band is identically zero on
  recorded rounds by construction. If a report calls this uncertainty, that
  report is wrong.
- **The cascade, Deffuant dynamics, and controversy weighting are
  reparameterizations, not fitted models.** The parameters have their rationale
  documented and their defaults stated, but nothing in this repository fits them
  to observed human behaviour. `calibrate/calibrate.ts` exists to do that
  fitting and has **no production caller** — its own header calls calibrating a
  simulation against its own output "circular validation", and that warning has
  not yet been resolved, only documented.
- **No run has been published end-to-end with a real model.** The committed demo
  and the gallery run against a deterministic mock brain. They exercise the
  pipeline; they are not evidence about the world.

## Why we say this plainly

Peer-reviewed work in 2026 measured LLM-simulated users against real people and
found them unreliable as proxies:

- Seshadri et al., *"Lost in Simulation"* (ACL 2026) — calibration error of
  15–20 points against real users, with results swinging 9 percentage points
  depending on which model simulated the user.
- Chen et al., *"When Synthetic Users Fail"* (arXiv 2607.26348) — no LLM beat the
  strongest non-LLM baseline on real survey data; segment targeting was wrong in
  roughly half of US cases.

So Murmur does not claim to predict reaction. It claims to help you find the
objections you have not thought of, faster than you can interview your way to
them — and to tell you which few questions are worth asking a real human. That
claim is falsifiable, and `bench/` is where we try to falsify it.

## Metrics that restate each other

Two figures in the report are functions of values printed nearby, not
independent measurements. Both are labelled as such in the output:

- **Polarization** = (committed ÷ population) × (0.5 + 0.5 × camp balance),
  computed from the three faction sizes shown directly above it.
- **Controversy** = a weighted mix of polarization (40), negative-sentiment
  engagement share (30), and escalation density (30). Its drivers are listed
  beneath it, so the arithmetic is checkable.

Anything not listed here is either engine-computed from the run or explicitly
flagged in the report as a limitation.

## How to argue with a report

1. **Check the citations.** Every risk and quote names a post id; open it.
2. **Check the arithmetic.** The methodology appendix in every report states the
   formulas and the live config values used for that run.
3. **Ignore the sentiment decimals.** "−0.42" means "the model wrote more
   negative words here", not "the crowd was 42% opposed". A one-hundredth change
   is noise; the direction and the *arguments* are the content.
4. **Take the objections, test them yourself.** The intended output is a list of
   things to check with real people, not a number to put in a board deck.
